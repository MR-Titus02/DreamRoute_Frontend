# DreamRoute route and page inventory

The inventory below reflects `src/App.jsx` and the current page/component implementations. “Preserve” records existing behavior to retain during redesign; API descriptions come from client call sites, not an independently inspected backend contract.

| Route / screen | Users and purpose | Current layout and functionality | Dependencies / states | Main improvements; preserve |
|---|---|---|---|---|
| `/` — `LandingPage` | Public visitors; explain DreamRoute and convert to signup/contact | Light-first page with concise product hero, workflow, supported feature list, institution application section, and labeled contact form | Contact POST retains existing four-field payload; signup and institution-request navigation. Contact has pending/success/error feedback | Phase 3 complete: removed unsupported static metrics and dead footer links, kept copy grounded in existing profile/roadmap/course/institution workflows, added responsive navigation and accessible form labels/status feedback. Existing API URL and payload remain unchanged from the current worktree. |
| `/login` — `Login` | Learners, admins, institutions; authenticate | Dark glass card, email/password, password reveal, Google redirect, forgot-password link | `/auth/login`, OAuth URL, AuthContext; inline API error | Standardize accessible fields, pending/error states, and social auth appearance. Preserve role redirects and password visibility. |
| `/signup` — `Signup` | New student accounts | Dark glass card; name/email/password/confirmation, reveal controls, Google redirect | `/auth/register`, AuthContext; browser alerts on error/password mismatch | Keep student registration and auto-login; accessible validation and submit state; align OAuth origin through existing configuration when endpoint is known. |
| `/dashboard` — `Dashboard` | Signed-in learner; roadmap overview and next actions | Dark dashboard shell, onboarding dialogs, career summary, completion progress and roadmap steps | `fetchRoadmap`, `fetchProgress`, AuthContext/localStorage; loading branch, console-only failure | Keep onboarding, progress calculation and roadmap navigation; provide explicit error/empty states and consistent data presentation. Route is currently not protected. |
| `/dashboard/roadmap` and `/roadmap` — `Roadmap` | Learner; inspect steps and update status | Standalone Navbar, dark timeline, expandable detail, status selector, premium modal | Roadmap/progress APIs, plans modal; loading/error states; progress update errors only logged | Unify shell and theme; accessible status and timeline; handle failed optimistic updates and empty roadmap. Preserve course/institution associations, status changes, premium gate. |
| `/dashboard/courses` — `Courses` | Learner; search/filter/paginate available courses and inspect details | Dashboard shell, dense filters, course-card grid, custom modal | Direct Axios calls to courses/institutions; client-side filtering and pagination; errors only logged | Fix filter/layout responsiveness, implement all visible filters consistently, keyboard accessible details, loading/error states. Preserve course data/filtering/detail functions. |
| `/dashboard/analytics` — `Analytics` | Learner; view usage/activity summaries | Dashboard shell with stat cards | `/analytics/:userId`; no explicit error state; null analytics is rendered as loading | Preserve API-backed metrics; distinguish pending, empty, and failure; improve hierarchy and avoid invented visualizations. |
| `/dashboard/settings` — `Settings` | Learner; update account/preferences | Dashboard shell, account and notification cards | GET/PUT `/users/:id`; fetch errors console-only; notification and dark-mode fields local-only | Preserve current account update contract; clearly identify unsupported settings and make status/error states visible. |
| `/dashboard/career-path` — `CareerPathFlow` | Learner; view/regenerate visual career map | Standalone Navbar and large React Flow canvas; custom nodes and plan modal | `/career/:userId`, `/career/generate`; premium check; error/loading states | Unify shell, improve canvas/mobile alternative and control labels; preserve graph and premium/regeneration flow. |
| `/userdetails` — `UserInfo` | Learner onboarding; capture profile and career preferences | Three-step dark form with progress meter; generates personalized roadmaps at final submit | `/profile`, `/roadmap`, `/career/generate`; local state/alerts, spinner | Keep fields, step progression, validation and generation sequence; add semantic labels/errors, submission failure recovery, and responsive form rhythm. |
| `/feedback` — `Feedback` | Learner; submit course/institution rating | Standalone dark glass form with hard-coded targets and star rating | Local-only submit (`console.log`), no persistence/API | Do not claim feedback is saved; connect only to a verified API contract. Preserve type/target/rating/message interaction once persistence is verified; make rating keyboard accessible. |
| `/submit-course` — `Submit_Course` | Intended institution/course submitter | Standalone dark form for course request; local-only success message | No API request; local state only | Verify intended owner and contract before connecting. | `/institution/requests` — `RequestInstitution` | Institution applicant; submit onboarding request | Standalone dark form; email may prefill from auth | POST `/institutions/requests`; status/error message; route currently unprotected | Preserve request shape and visible outcome; add form semantics/pending state, decide access based on existing user flows without inventing permissions. |
| `/institution` — `InstitutionDashboard` | Institution user; view course count | Institution shell, one count card | GET `/institutions/:institutionId/courses`; missing institution id only logged | Preserve count; add clear empty/error/loading states and useful real data only. | `/institution/courses` — `ManageCourses` | Institution user; create/edit/delete courses | Institution shell, card grid, modal form | Institution course GET; `/courses` POST/PUT/DELETE; errors logged; confirmation absent | Preserve CRUD and fields; provide accessible modal, validation, pending/error/empty states, and deletion confirmation. Route is role-protected. |
| `/institution/settings` — `InstitutionSettings` | Institution user; edit profile or delete account | Institution shell, form and destructive action | GET/PUT institution; DELETE user; alert/confirm; hook dependency warning; navigation to `/register` (not registered) after delete | Preserve API calls and explicit confirmation; improve state/reporting and resolve destination to an existing route only after behavior review. | `/admin` — `AdminDashboard` | Admin; inspect counts/login history | Admin shell, summary cards, role filter, page-size selector, paginated table | GET users/courses/login-logs; loading flag and console-only error | Preserve API-derived counts, filters and pagination; accessible responsive table, explicit error state. | `/admin/users` — `UserManagement` | Admin; search/sort/change role/delete users | Admin shell, user list, role selector, delete dialog, pagination | GET/PUT/DELETE user/admin endpoints; no explicit loading/error handling | Preserve controls and confirmation; ensure mobile table/list usability, safe action feedback, empty/error states. | `/admin/courses` — `CourseManagement` | Admin; create/review/delete courses | Admin shell, create form, filters/sort/pagination, dialogs | Courses/institutions CRUD and status endpoints; alerts/console errors | Preserve workflow and role checks; improve form labeling, action feedback, destructive confirmation, and empty/error states. Route is role-protected. |
| `/admin/institutions` — `InstitutionManagement` | Admin; manage institutions and requests | Admin shell, institution search/create, course lookup, approval/rejection workflows | Institution/users/admin endpoints; errors logged | Preserve institution/request operations and existing role-gated access; clarify separate sections and provide loading/error/empty feedback. Route is role-protected. |
| `/forgot-password` — `ForgotPassword` | Public user; request reset link | Standalone dark form | POST `/auth/forgot-password`; inline message/error | Preserve request/result behavior; connect label, pending state, and accessible announcements. |
| `/reset-password/:token` — `ResetPassword` | Public user with reset token; set new password | Standalone dark form | POST `/auth/reset-password/:token`; redirect to login after success | Preserve token route and success redirect; add password feedback and pending/error states without altering auth logic. |
| `/oauth-redirect` — `OAuthRedirect` | OAuth return flow | Minimal loading message; reads query params and logs user in | Query token/name/email/role/id; AuthContext; effect has missing dependency warning | Preserve parsing and role routing; communicate failure clearly and avoid exposing URL credentials beyond existing auth requirements. |
| `/plans` — `PlansPage` | Prospective subscriber; compare plans | Standalone dark three-plan cards; selection writes localStorage and navigates to payment | Hard-coded plan descriptions/feature list; no server request | Verify plan/pricing claims against backend/product configuration; preserve plan selection only where supported. |
| `/payment-methods` — `PaymentMethodsPage` | Signed-in subscriber; start Stripe checkout | Standalone plan selector and CTA | Stripe checkout session endpoint; error state declared but not set; unauthenticated alert | Preserve checkout contract; unify with plans and surface errors/pending state; confirm public key naming/configuration before integration changes. |

| `/unauthorized` — `Unauthorized` | Authenticated user with wrong role | Standalone error state and home button | Local navigation only | Preserve access-denied meaning; align shell/tokens and ensure destination is helpful. |
| `*` — `NotFound` | Any visitor; unknown path | Standalone 404 with home link | Router catch-all | Preserve catch-all and home action; use router navigation and shared visual system. |
| `/test` — `TestPage` | Development/test screen | Static dark promo sections | CTA links to unregistered `/get-started` | Mark as non-production/test scope; do not add a route or claims without product approval. |
| No route — `Index.jsx` | Unclear; alternate landing prototype | Light blue/purple landing page with feature cards and hard-coded stats | No API integration; CTA links to dashboard/demo | Keep outside routed product unless explicitly selected; remove unsupported stats before future use. |

## Shared surfaces and reusable UI

| Surface | Current role | Current behavior | Redesign focus |
|---|---|---|---|
| `DashboardLayout`, `AdminLayout`, `InstitutionLayout` | Learner, admin and institution shells | Similar dark fixed sidebar/header/footer, account dropdown; learner/institution include ChatBot | Consolidate shared shell behavior where practical; role-specific navigation must preserve existing access, with mobile and active-route states tested. |
| `Navbar`, `Sidebar`, `BackButton` | Alternate/general navigation | Navbar duplicates learner links; Sidebar is a simple admin link list; BackButton supports back/destination use | Reduce parallel navigation patterns; use router-aware links and semantic buttons. |
| `ChatBot` | Learner/institution assistant | Floating control, local transcript, POST `/chat`, typing and error text | Preserve endpoint/message behavior; add accessible dialog semantics, input labeling, request error/retry handling, and small-screen sizing. |
| `components/ui/*` | Shared primitives | Radix wrappers and CVA button variants; standard shadcn-style semantic class names | Wire semantic tokens, establish consistent focus and states, then migrate pages incrementally without removing existing behaviors. |
| `AuthContext`, API modules | Application services | Local storage auth; Axios interceptor; roadmap API helper | Preserve auth/API contracts; verify backend before normalizing hard-coded origins or request behavior. |
